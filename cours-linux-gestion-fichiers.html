1. Les types de fichiers

Sous Unix, il existe 7 types de fichiers, regroupés en 3 catégories :

CatégorieType(s)Rôle
Fichiers ordinaires1 typeTexte, code exécutable, données binaires. Unix ne fait aucune supposition sur leur contenu et ignore leur extension.
Répertoires1 typeFichiers dont le rôle est de contenir d'autres fichiers, pour organiser et hiérarchiser le système.
Fichiers spéciaux5 typesLien symbolique, périphérique mode caractère, périphérique mode bloc, socket, tube nommé (FIFO)
ATTENTION
Un fichier sans extension contenant du texte peut très bien être exécuté sous Unix : contrairement à Windows, l'extension n'est qu'une convention pour l'utilisateur (et les gestionnaires de fichiers graphiques), elle n'a aucun rôle pour le système lui-même.

Rappel sur les deux types de fichiers de périphériques :

ModePrincipe
BlocLecture/écriture par blocs d'octets (nombre fixé), à des emplacements précis
CaractèreLecture/écriture octet par octet, au fur et à mesure
À RETENIR
« Sous Unix, tout est fichier ! » Cette particularité simplifie l'écriture de programmes : envoyer une page à l'impression ou un message sur le réseau se fait comme une simple écriture dans un fichier ordinaire, le noyau se chargeant du reste.

2. Organisation en arborescence

Les répertoires organisent les fichiers en une hiérarchie arborescente. Le répertoire / (racine) est immuable et ne peut être placé dans un autre répertoire. Sous Unix, il n'existe pas d'unité de disque comme C: ou D: : les disques/partitions apparaissent comme des répertoires de cette arborescence.

Règles de nommage des fichiers :

  • Tous les caractères sont autorisés, sauf le / (slash) ;
  • Le système est sensible à la casse : toto et Toto sont deux fichiers différents ;
  • Un fichier est caché si son nom commence par un point (ex : .bashrc) — il reste accessible mais n'apparaît que s'il est explicitement demandé.
ATTENTION
La sensibilité à la casse a des exceptions pour certains systèmes de fichiers, notamment ceux utilisés par la plupart des clés USB et cartes mémoire (FAT/FAT32, voir section 5).

La racine contient un certain nombre de répertoires standards, chacun avec un rôle bien défini :

RépertoireRôle
binCommandes élémentaires accessibles à tous les utilisateurs
bootFichiers nécessaires à l'amorçage (démarrage) du système
devFichiers spéciaux de périphériques
etcFichiers de configuration du système
homeRépertoires personnels des utilisateurs
libLibrairies partagées élémentaires et modules du noyau
mediaPoints d'apparition des médias amovibles (clé USB, CD/DVD...) lors du branchement
mntMontage temporaire de systèmes de fichiers
optApplications tierces
procRépertoire virtuel (créé par le noyau) : informations et réglages sur les processus et le système
rootRépertoire personnel de l'administrateur (root)
sbinCommandes élémentaires d'administration
srvDonnées des services (notamment réseau) hébergés par le système
sysRépertoire virtuel créé par le noyau : informations/réglages système et périphériques
tmpFichiers temporaires, potentiellement supprimés au redémarrage
usrHiérarchie secondaire (bin, lib, sbin...) contenant la majorité des outils non essentiels au démarrage
varDonnées variables : journaux système, files d'impression, boîtes mail...

3. Références absolues et relatives des fichiers

Le nom d'un fichier n'a de sens que dans le répertoire où il apparaît : un même nom (ex : fic1) peut exister dans deux répertoires différents sans lien entre eux. Il faut donc toujours indiquer, d'une manière ou d'une autre, le répertoire dans lequel se trouve le fichier visé. Deux méthodes existent :

RéférencePrincipeSigne distinctif
AbsolueDepuis la racine /, en énumérant les répertoires traversésCommence toujours par /
RelativeDepuis le répertoire de travail (working directory)Ne commence jamais par /
À RETENIR — vocabulaire précis
On distingue le chemin d'un fichier (sa référence absolue ou relative) du chemin menant à ce fichier (le chemin du répertoire qui le contient). Si le fichier ciblé se trouve directement dans le répertoire de travail, sa référence relative est simplement son nom.

Exemple — référence absolue du répertoire essais : /home/cpb/public/unix/essais (on peut ajouter un / final, ce qui revient au même — mais pas pour un fichier, qui n'est pas un répertoire).

Chaque processus (dont un shell interactif) possède un répertoire de travail. À l'ouverture d'un terminal, il s'agit initialement du répertoire d'accueil de l'utilisateur. La commande cd permet de le changer (voir section 6).

4. Les répertoires spéciaux . et ..

Dans tout répertoire existent deux répertoires particuliers :

NomDésigne
. (point)Le répertoire qui le contient (son propre répertoire)
.. (point-point)Le répertoire parent de son répertoire parent (le "grand-parent")

On peut donc désigner le répertoire de travail par un simple point : cp /etc/passwd . copie /etc/passwd dans le répertoire de travail. Le répertoire .. de la racine désigne la racine elle-même.

À RETENIR — une référence n'est jamais unique
Avec /home/toto comme répertoire de travail, les références suivantes désignent toutes le même fichier mbox de toto : 
mbox
./mbox
././mbox
/home/./toto/./mbox
/./home/toto/mbox

5. Disques, partitions et systèmes de fichiers

Les unités de stockage (disques durs, clés USB, CD-ROM...) sont associées à une partie de l'arborescence : une partition est montée sur un répertoire existant appelé point de montage. La commande mount affiche les montages actifs et permet d'en créer ; umount démonte une partition.

$ mount
/dev/sda1 on / type ext3 (rw,errors=remount-ro)
/dev/sda9 on /home type ext3 (rw,usrquota)
/dev/sda8 on /tmp type ext3 (rw)
proc on /proc type proc (rw,noexec,nosuid,nodev)

Un système Unix nécessite au minimum deux partitions au démarrage : une pour la racine, et une partition swap (échange), réservée à la gestion mémoire du noyau et invisible dans l'arborescence. Les administrateurs créent souvent une partition séparée pour /home, pour préserver les données utilisateurs lors d'une réinstallation du système.

Sur un Linux récent, les supports amovibles sont montés automatiquement dans /media. Les montages au démarrage sont configurés dans /etc/fstab. Chaque disque et partition apparaît comme un fichier de périphérique en mode bloc dans /dev (ex : /dev/sda, /dev/sda1...), listés aussi dans /proc/partitions. L'utilitaire fdisk -l affiche (et permet de modifier) la table des partitions.

Formats de systèmes de fichiers

SystèmeCaractéristiques
FATAncien (MS-DOS/Windows), noms limités à 8+3 caractères, sans casse
FAT32Clés USB/cartes mémoire, noms ≤ 255 caractères sans casse, fichiers ≤ 4 Gio, partitions ≤ 2 Tio
NTFSWindows récent, fichiers ≤ 16 Tio, partitions ≤ 256 Tio
ext4Linux, fichiers ≤ 16 Tio, partitions ≤ 1 Eio
ATTENTION — Ko et Kio
Officiellement, Ko (kilo-octet) désigne 1000 octets (puissance de 10), tandis que Kio (kibioctet) désigne 1024 octets (puissance de 2). L'usage informatique confond souvent les deux, ce qui prête à confusion — le support de cours utilise Kio/Mio/Gio/Tio pour rester rigoureux.

Un bloc logique est la plus petite unité que le système de fichiers alloue pour stocker un fichier : un fichier de 3 octets occupe déjà un bloc logique entier (ex : 1 Kio), et un fichier de 1200 octets en occupe 2. La taille du bloc logique doit être un multiple de la taille du bloc physique du disque (souvent 4 Kio aujourd'hui).

6. Navigation : cd et pwd

cd (change directory, commande interne) — Synopsis : cd [répertoire]

  • cd sans argument : va au répertoire d'accueil de l'utilisateur ;
  • cd - : revient au répertoire de travail précédent (avant le cd précédent) ;
  • Sinon, l'argument est une référence (absolue ou relative) vers un répertoire existant.
toto@allegro:~$ cd projets/bidule
toto@allegro:~/projets/bidule$ cd /usr/bin
toto@allegro:/usr/bin$ cd -
/home/toto/projets/bidule

pwd (print working directory, commande interne) — affiche la référence absolue du répertoire de travail, sans aucun argument.

À RETENIR
Le prompt du shell affiche souvent une indication du répertoire de travail (parfois abrégée, ex : ~ pour le répertoire d'accueil), mais pwd donne toujours le chemin complet et fiable.

7. La commande ls en détail

Synopsis complet : ls [-adFhilrRStuU] [--color=(none|always|auto)] {référence}

OptionEffet
-aAffiche aussi les fichiers cachés (y compris . et ..)
-lAffichage détaillé (long)
-dAffiche les infos sur le répertoire lui-même, pas son contenu
-FAjoute un symbole selon le type : * exécutable, / répertoire, @ lien symbolique, | tube nommé
-RAffiche récursivement le contenu des sous-répertoires
-STrie par taille décroissante
-tTrie par date de modification (plus récent d'abord)
-uTrie par date d'accès plutôt que de modification
-UDésactive tout tri (ordre d'apparition dans le répertoire)
-rInverse l'ordre de tri (sauf avec -U)
--color=autoColore les noms selon leur type (nécessite le droit d'exécution sur le répertoire)
ATTENTION — comprendre -d
ls -l un-rep affiche le contenu de un-rep avec détails. ls -ld un-rep affiche les détails sur un-rep lui-même, pas son contenu. C'est une confusion très fréquente chez les débutants.

Lecture complète d'une ligne ls -l

total 12
-rw-r--r--  1 cpb  prof   1240  12 sept 10:32  fic1
drwxr-x-w-  2 cpb  prof   4096  12 sept 10:15  un-rep

La première ligne total ... indique le nombre de blocs occupés par les fichiers affichés (taille de bloc généralement 512 ou 1024 Kio). Chaque ligne suivante contient, dans l'ordre : le type de fichier, les 9 caractères de permissions (section 10-11), le nombre de liens physiques, l'utilisateur propriétaire, le groupe propriétaire, la taille en octets, la date de dernière modification, et le nom.

8. Créer, copier, déplacer, supprimer

mkdir — créer des répertoires

Synopsis : mkdir [-vp] référence {référence}. Sans -p, tous les répertoires intermédiaires du chemin doivent déjà exister.

rmdir — supprimer des répertoires vides

Synopsis : rmdir [-vp] référence {référence}. Avec -p, supprime aussi les répertoires parents s'ils deviennent vides. La suppression, si autorisée, est irréversible.

cp — copier des fichiers

Synopsis : cp [-adfirpv] source {source} destination

OptionEffet
-rAutorise la copie de répertoires et de leur contenu
-fForce l'écrasement (supprime la destination avant de copier si besoin)
-iDemande confirmation avant d'écraser un fichier
-pConserve propriétaire/groupe, permissions et dates de la source
-aPréserve un maximum d'attributs (active aussi -d et -r)
À RETENIR
Un fichier créé par copie appartient à l'utilisateur qui exécute la copie (pas au propriétaire de la source), avec pour permissions celles de la source moins celles du masque umask (section 11). Si la destination existe déjà, elle garde son propriétaire, son groupe et ses permissions : seul le contenu change.

mv — déplacer ou renommer

Synopsis : mv [-ivf] source {source} destination. Renomme si la destination n'existe pas encore (et qu'il n'y a qu'une source), sinon déplace dans le répertoire destination.

ATTENTION — permissions nécessaires pour mv
Pour déplacer/renommer un fichier au sein d'une même partition, il faut le droit d'écriture et d'exécution sur les répertoires source ET destination — aucun droit sur le fichier lui-même n'est requis. Un déplacement peut ainsi écraser un fichier existant à la destination sans que ses permissions n'entrent en jeu : seules comptent celles du répertoire destination.

rm — supprimer des fichiers

Synopsis : rm [-ifrv] référence {référence}. Sans -r, impossible de supprimer un répertoire. -f annule toute demande de confirmation, y compris pour un fichier sans droit d'écriture dont on est propriétaire.

9. Surveiller l'espace disque : df, du, quota

df (disk free) — occupation des systèmes de fichiers

Synopsis : df [-H] {référence}. Affiche, pour chaque système de fichiers monté : son nom, sa taille, les blocs utilisés/disponibles, le pourcentage d'occupation et son point de montage. -H affiche des quantités plus lisibles pour un humain.

du (disk usage) — taille de fichiers ou répertoires

Synopsis : du [-askbhc] {référence}. La "taille" d'un répertoire inclut toute son arborescence.

OptionEffet
-aAffiche aussi la taille de chaque fichier (pas seulement les répertoires)
-sN'affiche que le total pour chaque argument (summarize)
-hAffichage lisible (K, M, G)
-cAffiche aussi le total cumulé de tous les arguments

quota — limite d'occupation disque

Synopsis : quota / quota -u utilisateur / quota -g groupe. Un quota peut limiter le nombre de blocs utilisés et/ou le nombre de fichiers créés. Seul root peut consulter les quotas d'un autre utilisateur ou groupe.

10. Propriété et permissions : les principes

Le système vérifie, pour chaque opération demandée sur un fichier, 5 informations :

  1. L'utilisateur qui tente l'opération ;
  2. Ses groupes ;
  3. Le propriétaire du fichier ;
  4. Le groupe du fichier ;
  5. Les permissions du fichier.

Les permissions sont divisées en 3 catégories : les droits du propriétaire, ceux des membres du groupe du fichier, et ceux des autres utilisateurs. Un utilisateur n'utilise que les droits de sa catégorie la plus spécifique (propriétaire, sinon groupe, sinon autre) — jamais un cumul.

ATTENTION
Le propriétaire d'un fichier peut posséder moins de droits dessus qu'un autre utilisateur ! Mais s'il peut y accéder, il reste toujours capable de se redonner les droits qu'il veut (avec chmod).

Sens différent selon fichier ou répertoire

DroitSur un fichierSur un répertoire
Lecture (r)Lire son contenuLister son contenu (ex : avec ls)
Écriture (w)Modifier son contenu (n'affecte pas sa suppression)Ajouter, supprimer ou renommer un fichier dedans
Exécution (x)Exécuter le fichier (binaire, ou script si aussi lisible)Traverser le répertoire : y entrer, y référencer un fichier, en obtenir les détails
À RETENIR
Sans le droit d'exécution sur un répertoire, impossible de le "traverser" : ni cd dedans, ni référencer un fichier dans son arborescence, ni obtenir de détails sur son contenu — même avec le droit de lecture ! Le droit d'écriture sur un répertoire ne sert à rien sans le droit d'exécution associé.

11. Modifier les permissions : chmod, umask, chgrp, chown

chmod — modifier les permissions

Synopsis : chmod [-R] permissions référence {référence}. Il faut être propriétaire du fichier (ou root) pour le faire — aucune permission particulière sur le fichier lui-même n'est nécessaire.

Mode absolu (octal) : permissions est un nombre à 3 chiffres Cu Cg Co (propriétaire, groupe, autres), chacun de 0 à 7, obtenu en sommant 4 (lecture) + 2 (écriture) + 1 (exécution) :

chmod 640 fic1   # propriétaire: rw- (6), groupe: r-- (4), autres: --- (0)
chmod 751 rep    # propriétaire: rwx (7), groupe: r-x (5), autres: --x (1)

Mode symbolique : (qui)(opérateur)(quoi), répétable en séparant par des virgules (sans espace) :

QuiOpérateurQuoi
u propriétaire, g groupe, o autres, a tous+ ajoute, - enlève, = fixe exactementr, w, x (combinables)
chmod u+x script.sh          # ajoute l'exécution pour le propriétaire
chmod go=x,u+x fichier       # groupe et autres n'ont QUE l'exécution ; propriétaire garde ses droits + exécution
chmod g+r,o= fichier         # ajoute la lecture au groupe, retire tout aux autres
À RETENIR
Avec le mode symbolique, plusieurs opérations séparées par des virgules s'exécutent dans l'ordre d'écriture — l'ordre peut donc changer le résultat final si les opérations se chevauchent.

umask — masque de création de fichiers

Synopsis : umask [masque]. Indique, sous forme octale Cu Cg Co, les permissions à ne pas accorder lors de la création d'un fichier (rôle inverse de chmod). Le masque ne s'applique qu'à la création, jamais aux fichiers existants, et se transmet du shell aux programmes qu'il lance (mais pas aux autres shells).

ATTENTION
La plupart des utilitaires créent les fichiers ordinaires avec le mode 0666 (rw-rw-rw-), jamais avec l'exécution (sauf les compilateurs, en 0777). mkdir crée les répertoires en 0777. Le masque vient ensuite retirer des droits à ce mode initial.

chgrp — changer le groupe d'un fichier

Synopsis : chgrp [-fRv] groupe référence {référence}. Le propriétaire peut changer le groupe de son fichier par un groupe dont il est lui-même membre. Seul root peut l'attribuer à n'importe quel groupe existant.

chown — changer le propriétaire (et le groupe)

Synopsis : chown [-fRv] utilisateur[:[groupe]] référence {référence}. Seul root peut changer le propriétaire d'un fichier. Si utilisateur est suivi de :, le groupe change aussi (groupe indiqué, ou groupe primaire de l'utilisateur si omis).

chown bob fic1          # change seulement le propriétaire
chown bob: fic1         # change le propriétaire ET le groupe (groupe primaire de bob)
chown bob:dev fic1      # change le propriétaire et fixe le groupe à "dev"

12. Le 4e chiffre de chmod : SUID, SGID, sticky bit + hors programme

Le support évoque un "4e chiffre" de chmod, placé avant les trois habituels, "vu plus tard". Il s'agit de bits spéciaux :

BitValeurEffet
SUID4Sur un exécutable, il s'exécute avec les droits de son propriétaire plutôt que ceux de l'utilisateur qui le lance (ex : passwd)
SGID2Sur un exécutable, s'exécute avec les droits du groupe propriétaire ; sur un répertoire, les nouveaux fichiers créés dedans héritent de son groupe
Sticky bit1Sur un répertoire partagé en écriture (comme /tmp), seul le propriétaire d'un fichier peut le supprimer, même si d'autres ont le droit d'écriture sur le répertoire
chmod 4755 /usr/bin/passwd   # SUID + rwxr-xr-x
chmod 1777 /tmp              # sticky bit + rwxrwxrwx, comportement réel de /tmp

13. Liens physiques et liens symboliques : la commande ln + hors programme

Le support explique que chaque fichier existe sous forme d'un inode unique, et qu'un nom n'est qu'une référence vers cet inode (d'où le "nombre de liens physiques" affiché par ls -l). La commande ln permet de créer explicitement de nouvelles références :

ln fic1 fic1_bis        # lien physique : même inode, même données, compteur de liens +1
ln -s fic1 raccourci    # lien symbolique : nouveau fichier (type l) qui pointe vers fic1

Supprimer fic1 ne supprime pas les données tant qu'un lien physique existe encore ; en revanche, un lien symbolique devient immédiatement invalide ("lien brisé") si sa cible disparaît.

14. Les listes de contrôle d'accès (ACL) + hors programme

Le modèle propriétaire/groupe/autres est parfois trop limité (ex : donner un accès précis à un deuxième utilisateur spécifique sans créer de groupe dédié). Les ACL (Access Control Lists) permettent des permissions plus fines :

setfacl -m u:bob:rwx fic1   # donne à l'utilisateur bob, spécifiquement, tous les droits sur fic1
getfacl fic1                 # affiche les ACL en vigueur sur fic1
À RETENIR
Un fichier avec des ACL actives affiche un + après ses permissions classiques dans ls -l (ex : rwxr-xr-x+), signalant qu'il faut consulter getfacl pour la liste complète des droits réels.
