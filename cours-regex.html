1. Introduction : à quoi servent les regex ?

Une regex est un langage de motifs utilisé pour trois opérations principales : valider une chaîne (format d'un email), rechercher une occurrence dans un texte (trouver toutes les adresses IP d'un log), et remplacer du texte (anonymiser des numéros de téléphone). On les retrouve dans presque tous les langages : Python (re), JavaScript (RegExp), les commandes Unix grep/sed/awk, les éditeurs de code (recherche/remplacement avancée), les bases de données (REGEXP en SQL), et la validation de formulaires web.

Une regex se construit en assemblant deux types de briques :

  • des caractères littéraux qui se représentent eux-mêmes (a, 3, -) ;
  • des métacaractères qui portent un sens spécial (répétition, alternative, position...).
À RETENIR
Un moteur de regex lit le texte caractère par caractère et essaie de faire correspondre le motif à partir de chaque position possible, jusqu'à trouver une correspondance ou épuiser le texte. Comprendre ce fonctionnement séquentiel aide à anticiper le comportement d'un motif complexe.

2. Syntaxe de base : littéraux et métacaractères

Un caractère normal (lettre, chiffre) se représente lui-même : la regex chat trouve exactement la sous-chaîne "chat", où qu'elle soit dans le texte (sauf si elle est ancrée, voir section 5). Les métacaractères ont un sens spécial et doivent être échappés avec \ si on veut les utiliser littéralement.

MétacaractèreSignification
.N'importe quel caractère (sauf retour à la ligne, par défaut)
^Début de chaîne (ou de ligne en mode multiligne)
$Fin de chaîne (ou de ligne en mode multiligne)
\Échappement d'un métacaractère ou début d'une classe raccourcie
* + ? {}Quantificateurs (répétition)
[ ]Classe de caractères
( )Groupe (capturant par défaut)
|Alternance (OU)

Liste complète des caractères à échapper s'ils doivent être utilisés littéralement : . ^ $ * + ? { } [ ] \ | ( ).

ATTENTION
Pour chercher un point littéral dans une adresse IP, il faut écrire \. et non ., qui matcherait n'importe quel caractère. De même, pour chercher un + littéral (ex : un numéro international +33...), il faut écrire \+.

Exemple comparatif : sur le texte "192.168.1.1", la regex 192.168.1.1 (point non échappé) matche aussi "192a168a1a1", car . accepte n'importe quel caractère. La regex correcte est 192\.168\.1\.1.

3. Classes de caractères

Une classe [...] représente un seul caractère parmi un ensemble donné.

[abc]      # a, b ou c
[^abc]     # tout sauf a, b ou c (négation)
[a-z]      # une lettre minuscule
[A-Za-z0-9]# une lettre ou un chiffre
[a-zA-Z0-9_-]# lettres, chiffres, underscore ou tiret

Raccourcis très utilisés (équivalents en majuscule = négation) :

RaccourciÉquivaut àSignification
\d[0-9]Un chiffre
\D[^0-9]Tout sauf un chiffre
\w[A-Za-z0-9_]Caractère "mot"
\W[^A-Za-z0-9_]Tout sauf un caractère mot
\s[ \t\n\r\f\v]Espace, tabulation, saut de ligne
\STout sauf un espace
ATTENTION — le tiret dans une classe
À l'intérieur de [...], le tiret - sert normalement à définir un intervalle (a-z). Pour l'utiliser littéralement, placez-le en premier ou en dernier de la classe : [a-z-] matche une minuscule OU un tiret. De même, ^ n'a un sens de négation que s'il est en première position de la classe ; ailleurs, c'est un caractère littéral : [a^z] matche "a", "^" ou "z".

Exemple : valider un code postal français à 5 chiffres : [0-9]{5} ou, de façon équivalente, \d{5}.

4. Quantificateurs

SymboleSignification
*0 fois ou plus
+1 fois ou plus
?0 ou 1 fois (rend aussi un quantificateur "paresseux" s'il suit un autre quantificateur)
{n}Exactement n fois
{n,}Au moins n fois
{n,m}Entre n et m fois (inclus)

Exemples comparés sur la chaîne "aaa" :

MotifRésultat sur "aaa"
a*Matche "aaa" (et matcherait aussi une chaîne vide)
a+Matche "aaa" (au moins 1 "a" requis)
a{2}Matche "aa" seulement (exactement 2)
a{1,2}Matche "aa" (2 premiers "a", le maximum autorisé)
ATTENTION — greedy vs lazy
Par défaut, les quantificateurs sont gourmands (greedy) : ils capturent le maximum possible, puis "rendent" des caractères si besoin pour que le reste du motif corresponde (backtracking). <.*> sur <b>texte</b> capture tout jusqu'au dernier > : "<b>texte</b>". En ajoutant ? après le quantificateur (.*?), il devient paresseux (lazy) et s'arrête à la première correspondance possible : "<b>".

Chaque quantificateur possède sa version paresseuse : *?, +?, ??, {n,m}?.

5. Ancres

AncreSignification
^Début de chaîne (ou de ligne si flag multiligne)
$Fin de chaîne (ou de ligne si flag multiligne)
\bFrontière de mot (limite entre \w et non-\w)
\BAbsence de frontière de mot

Exemple : \bchat\b trouve "chat" mais pas "chaton" ni "achat", car il n'y a pas de frontière de mot entre les lettres.

À RETENIR
Sans ancre, une regex peut correspondre à n'importe quelle sous-chaîne du texte. \d{3} trouve "123" dans "a123b". Avec les ancres ^\d{3}$, la chaîne entière doit être composée de 3 chiffres, ni plus ni moins.

6. Groupes, capture et alternance

(abc)      # groupe capturant n°1
(?:abc)    # groupe non capturant (regroupe sans créer de référence)
(a|b)      # alternance : a OU b
(?P<jour>\d{2})# groupe nommé (Python)

Les groupes capturants permettent de récupérer une sous-partie du texte trouvé (ex : extraire le nom de domaine d'une URL) et de réutiliser une valeur ailleurs dans le motif via une rétro-référence comme \1 (qui désigne le contenu déjà capturé par le premier groupe).

Exemple de rétro-référence : détecter un mot répété deux fois de suite, comme "le le" : \b(\w+)\s+\1\b. Le \1 impose que le deuxième mot soit identique au premier groupe capturé.

ATTENTION — numérotation des groupes
Les groupes capturants sont numérotés de gauche à droite, selon la position de leur parenthèse ouvrante, même s'ils sont imbriqués. Dans ((a)(b)), le groupe 1 est (a)(b), le groupe 2 est (a), le groupe 3 est (b).

L'alternance | s'applique à tout ce qui l'entoure dans le groupe ou dans la portée courante : gris|grise hors groupe matche "gris" OU "grise" indépendamment d'un éventuel contexte, alors que gris(e)? factorise le motif.

7. Lookahead et lookbehind (assertions)

Ces motifs vérifient un contexte sans le consommer (il n'apparaît pas dans le résultat capturé) :

MotifNomSignification
(?=...)Lookahead positifSuivi de ...
(?!...)Lookahead négatifNon suivi de ...
(?<=...)Lookbehind positifPrécédé de ...
(?<!...)Lookbehind négatifNon précédé de ...

Exemple : \d+(?=€) capture un nombre uniquement s'il est suivi du symbole €, sans inclure le € dans le résultat. Sur "12kg et 89€", seul "89" est trouvé.

Autre exemple utile : (?<=@)\w+ capture le nom de domaine juste après le @ d'un email, sans inclure le @.

ATTENTION
En Python, le lookbehind (?<=...) doit obligatoirement porter sur un motif de longueur fixe (pas de * ou + à l'intérieur), contrairement au lookahead qui accepte une longueur variable.

8. Flags (modificateurs)

FlagPythonEffet
ire.IGNORECASEIgnore la casse (majuscules/minuscules)
mre.MULTILINE^/$ matchent chaque ligne, pas juste la chaîne entière
sre.DOTALL. matche aussi le saut de ligne

Plusieurs flags peuvent se combiner : en Python, re.search(motif, texte, re.IGNORECASE | re.MULTILINE).

9. Le module re en Python

import re

# match : vérifie le DÉBUT de la chaîne uniquement
re.match(r"\d+", "42 pommes")        # -> trouve "42"
re.match(r"\d+", "il y a 42 pommes") # -> None (ne commence pas par un chiffre)

# fullmatch : la chaîne ENTIÈRE doit correspondre
re.fullmatch(r"\d+", "42")     # -> correspond
re.fullmatch(r"\d+", "42 ")    # -> None (espace en trop)

# search : cherche n'importe où dans la chaîne, renvoie la 1ère occurrence
re.search(r"\d+", "j'ai 42 pommes")  # -> trouve "42"

# findall : renvoie TOUTES les occurrences (sous forme de liste)
re.findall(r"\d+", "3 chats, 12 chiens") # -> ['3', '12']

# finditer : comme findall, mais renvoie des objets Match (position, groupes...)
for m in re.finditer(r"\d+", "3 chats, 12 chiens"):
    print(m.group(), m.start(), m.end())

# sub : remplace toutes les occurrences
re.sub(r"\d+", "N", "3 chats, 12 chiens")# -> "N chats, N chiens"
re.sub(r"\d+", "N", "3 chats, 12 chiens", count=1)# -> "N chats, 12 chiens"

# split : découpe une chaîne selon un motif
re.split(r"\s*,\s*", "pomme, poire,banane")# -> ['pomme', 'poire', 'banane']

# compile : pré-compile le motif (perf si réutilisé plusieurs fois)
motif = re.compile(r"(?P<code>\d{5})\s(?P<ville>\w+)")
m = motif.search("75001 Paris")
m.group("code")   # -> "75001"
m.group("ville")  # -> "Paris"
m.groupdict()     # -> {'code': '75001', 'ville': 'Paris'}
À RETENIR
Utilisez toujours des chaînes brutes (r"...") en Python pour écrire une regex : cela évite les conflits entre l'échappement Python (\n) et l'échappement regex (\d). Sans le r, "\d" peut fonctionner par chance, mais "\b" par exemple sera interprété comme un retour arrière (backspace) par Python et non comme une frontière de mot.
FonctionRôle

re.fullmatchTeste le motif sur la chaîne entière
re.searchCherche la première occurrence n'importe où
re.findallRenvoie toutes les occurrences (liste)
re.finditerRenvoie toutes les occurrences (itérateur d'objets Match)
re.subRemplace les occurrences
re.splitDécoupe une chaîne selon le motif

10. Backtracking catastrophique et ReDoS + hors programme

Certains motifs mal écrits, combinant des quantificateurs imbriqués comme (a+)+ ou (a|aa)+, peuvent provoquer une explosion du nombre de tentatives du moteur de regex face à une entrée qui ne correspond pas exactement (backtracking catastrophique). Sur une entrée de quelques dizaines de caractères bien choisie, le temps de calcul peut devenir exponentiel et bloquer une application : c'est une vraie faille de sécurité appelée ReDoS (Regular Expression Denial of Service).

ATTENTION
Évitez d'imbriquer deux quantificateurs qui peuvent matcher la même chose ((a+)+, (a*)*). Préférez des motifs qui ne laissent pas d'ambiguïté sur la façon de "découper" le texte, ou utilisez des outils comme regex101 (mode "debugger") pour visualiser le nombre d'étapes exécutées par le moteur.

À RETENIR
Toujours vérifier dans quel environnement une regex va s'exécuter avant de la copier d'un outil à l'autre : un motif qui fonctionne dans regex101 en mode Python ne fonctionnera pas forcément tel quel avec grep en shell.

12. Écrire des regex lisibles avec re.VERBOSE + hors programme

Un motif complexe devient vite illisible sur une seule ligne. Le flag re.VERBOSE (ou re.X) permet d'ajouter des espaces et des commentaires dans le motif, ignorés à l'exécution :

import re

motif = re.compile(r"""
    ^(?P<code>\d{5})   # code postal, 5 chiffres
    \s+                 # un ou plusieurs espaces
    (?P<ville>[A-Za-zÀ-ÿ\-\s]+)$  # nom de ville
""", re.VERBOSE)

Cette approche est très utile en entreprise pour documenter un motif complexe directement dans le code, sans dépendre d'un commentaire séparé qui risque de devenir obsolète.

13. Étude de cas : valider un mot de passe robuste + hors programme

Cahier des charges : au moins 8 caractères, une majuscule, une minuscule, un chiffre, un caractère spécial. On combine plusieurs lookaheads positifs ancrés en début de chaîne, chacun vérifiant une condition indépendamment, puis un motif final qui consomme la chaîne :

^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^\w\s]).{8,}$
BlocRôle
(?=.*[a-z])Vérifie la présence d'au moins une minuscule, n'importe où
(?=.*[A-Z])Vérifie la présence d'au moins une majuscule
(?=.*\d)Vérifie la présence d'au moins un chiffre
(?=.*[^\w\s])Vérifie la présence d'au moins un caractère spécial
.{8,}$Longueur minimale de 8, consomme réellement la chaîne
À RETENIR
C'est l'exemple type qui montre la puissance des lookaheads : chaque condition est vérifiée indépendamment, sans imposer d'ordre entre la majuscule, le chiffre et le caractère spécial, contrairement à ce qu'un motif "linéaire" classique pourrait imposer.
